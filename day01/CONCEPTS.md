# 延伸知識：函式拆分與 AI 生成程式碼的第一個地雷

這份不是規格，是背景知識。看完不會讓你多拿分，但會讓你看得懂為什麼規格要這樣寫。

## 為什麼要拆三個函式，不是一個 `main()` 全包

`mean` / `above_mean` / `relative_to_mean` 各自只做一件事，這是 **pure function（純函式）**：輸出只由輸入決定，不碰檔案、不印東西、不改全域變數。好處很具體：

- 測試 `mean([1, 2, 3])` 不需要準備任何環境，呼叫完直接斷言結果。
- `above_mean` 需要平均值時直接呼叫 `mean`，不用重算一次、也不會兩處平均值算法不同步。
- 之後要把「平均」換成「中位數」，只改一個函式，呼叫端不用動。

如果全部塞進 `main()`，這三件事會變成互相糾纏的區域變數，你想單獨測某一段就得把整個流程跑一遍。

## AI 生成程式碼在這裡常見的兩個地雷

1. **重複計算**：AI 常常在 `above_mean` 和 `relative_to_mean` 裡各自重新算一次 `sum(values) / len(values)`，而不是呼叫 `mean()`。表面上能跑，但如果之後平均值的定義要改（例如要排除離群值），你得在好幾個地方同步改，很容易漏掉一處。看 AI 生成的程式碼時，第一件事就是找「這段計算是不是在別的地方也出現過」。

2. **邊界條件先寫死、後補丁**：直接叫 AI 寫這個函式，很多時候會先生成一版「開心路徑」（happy path，只考慮正常輸入的版本），你追問「空列表呢？」它才補上 `if not values: raise ValueError`。這沒問題，但如果你沒有主動問，這個檢查可能永遠不會出現——直到有人真的傳一個空列表進來，程式在生產環境噴出難懂的 `ZeroDivisionError`。**能不能主動想到要問這個問題，比會不會寫這行 `if` 更重要。**

## 為什麼空列表要拋例外，而不是回傳 0 或 None

回傳 `0.0` 看起來「安全」，但 0 是個合法的平均值（例如 `[0, 0, 0]` 的平均值真的是 0），呼叫端沒辦法分辨「這是真的平均值 0」還是「這其實是空輸入」。回傳 `None` 稍微好一點，但每個呼叫端都要記得檢查 `None`，一旦漏檢查就會在後面某處爆出更難追的錯誤。`raise ValueError` 讓錯誤在**最早發生的地方**現形，而不是被悄悄吞掉、在幾層呼叫之後才炸開。這是個一般原則：**能讓錯誤晚出現不代表應該讓錯誤晚出現。**

## 型別標註 `list[float] -> float` 除了給人看，還做了什麼

型別標註本身在執行期不會被強制檢查（Python 不會因為你傳字串進去就自動報錯），但它有兩個實務用途：

- 讓 `mypy`、IDE 的自動完成、AI 工具（包括 Claude Code）在讀你的程式碼時，能推論出這個函式的輸入輸出形狀，減少誤用或誤改的機率。
- 逼你自己想清楚「這個函式到底吃什麼、吐什麼」——寫標註的過程本身就是一種設計檢查。

之後幾天會陸續看到 dataclass（day10）、argparse 的型別轉換（day08），都是同一個精神：**讓形狀在程式碼裡是明確的，不要靠讀 docstring 或猜。**

## 「不得修改原始串列」背後：Python 傳的是參考，不是副本

規格說「不得修改原始串列」，背後的機制是 Python 的變數模型：`values` 這個參數名字，指向的是呼叫端傳進來的**同一個** list 物件，不是一份副本。這代表：

```python
def above_mean(values: list[float]) -> list[float]:
    values.sort()          # 危險：這會改到呼叫端手上的那個 list
    m = mean(values)
    return [v for v in values if v > m]
```

呼叫端寫 `scores = [3.0, 1.0, 2.0]; above_mean(scores)`，呼叫完之後 `scores` 已經被排序過了——呼叫端完全沒預期到自己的變數會被改變，這種「你只是想讀資料，卻不小心改到別人手上的東西」的 bug，叫做**別名（aliasing）問題**：兩個名字（呼叫端的 `scores`、函式裡的 `values`）指向同一塊記憶體。

對照組：

```python
def above_mean(values: list[float]) -> list[float]:
    values = values[:]     # 安全：先複製一份，後面的操作只影響這份複製
    values.sort()
    ...
```

或者更直接，優先選「回傳新結果，不動輸入」的寫法（例如用 `sorted(values)` 而不是 `values.sort()`——前者回傳新 list，後者原地排序並回傳 `None`）。**這也是為什麼這幾個函式被要求設計成 pure function：pure function 的其中一個隱含承諾，就是不動輸入。**

這件事在 `list[float]` 這種「只有一層、內容是不可變的 float」的資料結構上風險還算低——真正麻煩的是巢狀結構（list 裡面裝 dict、dict 裡面裝 list），這種情況下光複製最外層還不夠，day10 會接著講這個問題（shallow copy vs deep copy）。
